# 审核问题标记：跨会话继承设计

日期：2026-09-30。状态：第二阶段设计提案，尚未接入运行逻辑。
第一阶段已实现当前会话的标记状态筛选；本文件描述后续实现边界和验收条件。

## 1. 用户行为和状态语义

- 在会话 A 将问题标为“已忽略”，可选择将该决定应用到后续审核。
- 会话 B 仍正常审核、正常生成全部问题；满足严格匹配条件的问题显示“已忽略 · 继承”，并展示来源会话、标记时间、失效时间和忽略原因。
- 不把历史标记加入模型提示词，不让模型自行省略问题。
- “已修复”不自动变成新会话的已修复状态。新审核再次检出时，保持未标记，并提示“曾标记已修复，本次再次检出”，避免掩盖回归。
- 三种筛选状态始终为“已修复 / 已忽略 / 未标记”；“清除标记”是操作，不是第四种状态。“全部”用于取消状态限制。
- 推荐在新会话默认显示继承项及来源，用户可使用状态筛选查看未标记项；至少应明确显示继承数量，不能让新发现无提示地消失。是否继续沿用默认隐藏，由第二阶段的交互实现统一处理。

## 2. 当前代码和可复用边界

| 位置 | 当前行为 | 对设计的约束 |
| --- | --- | --- |
| `internal/viewer/static/session.js` | `localStorage` 以页面路径为键保存 `MarkID -> fixed/ignored` | 仅当前浏览器、站点来源和会话；服务端无法直接读到旧标记 |
| `internal/viewer/store.go:commentMarkID` | UUID + 评论序号；旧记录使用全部字段的散列和出现次数 | 保留为会话内身份，不能直接作为跨会话身份 |
| `internal/session/compare.go:findingKey` | 文件路径、类别、折叠空白后的代码；无代码时退回描述 | 适合对比候选检索，但同一代码可以存在多个不同问题，不可直接据此自动忽略 |
| `internal/viewer/templates/session.html` | 标记状态筛选在问题类型下方，接入现有分页 | 新继承状态应通过同一显示状态驱动计数和筛选 |

当前模型没有可依赖的稳定规则 ID。不可使用展示序号、记录 UUID、仅行号、仅问题标题或相似度作为自动继承依据。

## 3. 保存位置和作用域

推荐将第二阶段的权威状态保存到审核服务所在机器的独立标记目录，例如：

```text
~/.opencodereview/viewer-marks/<repo-key>/decisions.json
~/.opencodereview/viewer-marks/<repo-key>/sessions/<session-id>.json
```

以上路径是提案。不要把可修改状态混入现有不可变的会话 JSONL，不写入被审核仓库，不改变原始报告。

- `decisions.json`：可用于后续会话的忽略决定、撤销事件和版本。
- 会话侧文件：本次明确标记、显式“未标记”覆盖及继承来源快照。
- 同一个 viewer 服务下不同浏览器可读取相同状态；不同机器不自动同步。
- 仓库身份以本机规范化仓库路径和持久化标识绑定，不只使用仓库名或远端 URL。同名仓库、不同克隆和 worktree 默认隔离。
- 默认只在同一仓库、同一分支/审核目标及相同审核模式内继承。分支元数据缺失时不自动继承。跨分支共享不作为首版默认能力。
- `localStorage` 继续用于筛选/隐藏偏好；浏览器本地旧标记的迁移见第 7 节。

浏览器仓库级 `localStorage` 可以作为更小的替代实现，但仍受浏览器、端口、清理缓存、多个标签页写入竞争的限制，因此不建议作为长期权威存储。

## 4. 匹配：候选检索与自动继承分开

### 严格身份与上下文

新增版本化 `findingFingerprintV1`，保留原 `MarkID`。采用结构化字段序列化后 SHA-256，避免分隔符歧义。强匹配至少使用：

1. 仓库身份和相同审核作用域；
2. 仓库相对文件路径，统一路径分隔符，保留大小写语义；
3. 规范化类别、严重程度；严重程度升级不沿用旧决定；
4. 原始问题描述和现有代码的保守规范化值：仅统一 CRLF/LF、去除首尾空行；不折叠字符串字面量或 Python 缩进；
5. 从审核时冻结输入取得的文件内容摘要、审核规则/背景要求摘要。不能用打开历史页面时的工作区文件替代；
6. 如问题涉及跨文件依赖，还需上下文摘要一致。无法证明依赖范围时，仅在整个冻结审核输入摘要一致时自动继承。

行号、会话 ID、展示序号和建议代码不直接组成问题身份。行号可用于定位和发现歧义。
相同行号不能证明相同问题，建议代码改写也不能证明问题已变。

### 匹配决策

| 条件 | 处理 |
| --- | --- |
| 严格指纹及上下文一致、唯一匹配、有效期内的忽略决定 | 自动继承“已忽略”，保留来源 |
| 代码相同但模型描述改写、上下文无法证明一致 | 仅提示历史候选，保持未标记，允许人工确认 |
| 插入代码导致行号移动或文件重命名 | 首版仅提示候选；后续可用明确的重命名记录/上下文锚点加强匹配 |
| 相同片段在多个函数出现，或同一片段存在多个问题 | 要求一对一匹配；发生歧义不继承 |
| 代码、规则、作用域、类别或严重程度变化 | 不自动继承 |
| 缺少代码/路径/输入摘要的旧记录 | 保留会话内标记；不自动进行跨会话强匹配 |
| 历史为已修复而新会话再次检出 | 未标记 + 再次检出提示 |

首版优先避免误忽略，允许同一问题因描述改写而需要再次确认。不能宣称能识别所有语义相同的问题。
LLM/向量相似度如以后引入，仅供候选排序，不直接产生忽略决定。

## 5. 生命周期、时序与撤销

- 建议忽略有效期默认 30 天，用户可选择 7/30/90 天；这是待实现的产品默认值。
- 有效期从最后一次人工确认起算，浏览或自动继承不续期。
- 到期后新会话保持未标记，并提示历史忽略已到期。
- 代码或相关上下文改变即不自动继承，即使还没到日期也一样。
- 只继承新审核开始之前已建立的决定；后来在会话 A 做的标记不回溯改变更早启动的会话。
- 历史会话保留当时继承来源快照，另行显示“来源已过期/已撤销”；不重写历史审核结论。
- “清除标记”作用于当前会话：记录显式未标记覆盖，优先于继承，刷新后不重新套回。
- “清除全部标记”同样只影响当前会话中的所有问题，并创建必要的覆盖。
- 另设“停止后续继承”操作撤销仓库级忽略决定；不能把局部清除悄悄解释为全仓库撤销。
- 重复打开旧会话不能重新发布已撤销的决定；保存撤销版本/墓碑。
- 审核未成功覆盖某个文件时，不能因为问题没出现就判断已修复，也不能自动清理其历史决定。

## 6. 数据和接口草案

仓库决定字段：`schemaVersion`、`fingerprintVersion`、`decisionId`、`repoId`、`scope`、`fingerprint`、`contextDigest`、`state`、`reason`、`sourceSessionId`、`sourceMarkId`、`createdAt`、`confirmedAt`、`expiresAt`、`revokedAt`、`revision`。

会话覆盖字段：`sessionId`、`markId`、`state`（含显式 `unmarked`）、`origin`（manual/inherited）、`decisionId`、`decisionRevision`、`resolvedAt`。

- 优先级：当前会话人工覆盖 > 已解析的继承快照 > 尚未解析且满足条件的历史忽略 > 未标记。
- 拟增加独立 JSON 读写端点；客户端提交会话 ID、MarkID、操作、原因和预期 revision。服务端从原始审核记录计算指纹，不能信任客户端提交的路径或散列。
- 写入需检查同源请求、仓库/会话绑定和已有 viewer 写操作的验证机制；默认本机访问。服务暴露到网络时需有明确访问控制。
- 使用仓库级写锁、临时文件原子替换和乐观版本控制；冲突返回 409，不覆盖较新决定。
- 客户端只在保存成功后确认状态；失败显示保存错误，不让未保存标记呈现为已持久化。
- 文件损坏/未知 schema 时降级为未标记并提示，保留原文件供恢复；不静默清空。
- 定期按状态和保留期限清理失效记录，保留撤销版本，避免旧标签页恢复已撤销状态。
- 可先按需解析会话的有效状态，不必在每次页面访问时扫描所有历史 JSONL。

## 7. 兼容、迁移和导出

- 旧浏览器标记由用户明确选择导入；服务端不能直接读取浏览器存储。先预览会话内标记，验证每条 MarkID 属于目标仓库/会话。
- 旧“已修复”仅迁移为会话标记；旧“已忽略”默认也只迁移为会话标记。用户确认后才建立带新时间和有效期的后续忽略决定。
- 原始标记没有可靠创建时间，禁止伪造历史时间或静默获得永久有效期。
- 静态 HTML 保持离线查看能力，不提供服务端写入；可另提供带处理状态的导出选项，标明状态导出时间。
- 默认 JSON/Markdown/SARIF 继续输出完整原始审核结果。继承信息若导出，应置于明确的附加元数据，不能删除忽略项或更改发现总数。
- 删除仓库时一并处理其独立标记目录；删除单个会话时删除会话覆盖，仓库级决定保留最少来源信息并提示来源会话已删除。

## 8. 实施顺序和验收

1. 先实现并测试强指纹和候选匹配器，明确审核快照/规则摘要缺失时的降级路径。
2. 实现独立存储、版本控制、过期与撤销规则，测试跨标签页竞争和损坏恢复。
3. 增加端点和会话有效状态解析，再接入现有标记操作、计数、筛选和来源提示。
4. 补充旧标记迁移预览及可选状态导出；更新查看器文档和只读路由测试。

必须覆盖的验收情景：

- A 忽略，B 同作用域重复检出：严格匹配时显示继承标签；原始结果仍包含问题。
- A 标记已修复，B 再次检出：保持未标记并显示回归提示。
- 同名不同仓库/不同 worktree/不同分支不会串标记。
- UUID/展示序号变化不破坏可证明的匹配；行号移动和文案改写只能产生候选。
- 同片段不同问题、重复片段、一对多和多对一不自动继承。
- 上下文、代码、规则或严重程度变化时不会错误继承。
- 过期、未来时间、未知版本、撤销、反复打开旧页不会自动续期或复活决定。
- 清除单条/全部后刷新仍为未标记；撤销后后续会话不再继承。
- 后生成的决定不改变先启动的会话；失败或未覆盖文件不能视为已修复。
- 存储失败、并发写入、路径越界、跨仓库 ID 和跨源写入有明确错误且不丢失状态。
- 继承状态与严重程度、类型、搜索、分页、中英文及隐藏开关联动一致。
- 原始 JSONL 和默认导出保持完整；迁移须经明确操作且不能扩大默认作用域。
